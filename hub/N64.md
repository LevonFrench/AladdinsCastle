# Playing Nintendo 64 games from Hub

Open **VR games**. The Nintendo 64 shelf lists the games that `acvr-ps1`
(`setups/retro-ps1-vr`, with `--controls pad|wheel|aim`) runs through the
mupen64plus-next core in the headset: real 3D, the game's HUD on its own
steady panel, the world past the old frame where the game draws it, racers
steered with the left stick (triggers are gas and brake) and aiming by pointing.
Rolling the right controller to steer is an option of the launcher, off by default
(`launch-n64.ps1 <key> -RollSteer`, or `ACVR_N64_ROLL_STEER=1`); the Hub never turns it on.

Hub ships no emulator, core or game. You keep a small launcher script of your
own (Windows PowerShell, `launch-n64.ps1`) that knows, per key, your cartridge
dump, the core options, the controls map, the depth and the widescreen
settings. A `games.json` beside the script lists the keys. Each view of a game
is its own key: `<id>-3d` (real 3D), `<id>` (flat: open frame, 16:9 or 4:3),
`<id>-theatre` (the original 4:3 picture on a theatre screen). The ids are the
ones in `src/core/n64/N64.cpp` (`mario-kart-64`, `goldeneye`, `turok` and so on).
A game's page offers only the views your launcher lists, real 3D first.

## Set up, once

In **Set-up**, choose the launcher script for Nintendo 64 (setting
`n64Launcher`). A card says **Not ready** when the script is missing or has no
entry for that game.

## Start and stop

Start SteamVR with the headset connected first; Hub refuses to start the game
otherwise. Hub runs Windows PowerShell 5.1 from the system folder with
`-NoProfile -ExecutionPolicy Bypass -File <launcher> <key>`, with every
inherited `ACVR_*` variable removed and `ACVR_PS1_STOP_FILE` set to a stop file
of its own for that launch, under `user/runtime/` (acvr-ps1 serves both
systems). **Exit game** creates that file: the game saves and quits, and Hub
waits for it. Holding both stick clicks for 3 seconds in the headset does the same.
