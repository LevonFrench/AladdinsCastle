# VPX launch and monitoring findings

Read-only source inspection of official tag `v10.8.1-5436-af26b2d93`, commit `af26b2d9392b4c9ec3e3edff4bbd69562085a44c`. No VPX build, source copying, table capture or runtime acceptance. Each link names that immutable source.

1. **Play and exit modes.** `-Play` constructs `PlayTableCommand`, runs `Player::GameLoop`, destroys the player and returns. Normal application return is zero; caught `CException` returns -1, CLI errors generally exit 1, and forced-stop uses -9999. `-Minimized` and `-ExtMinimized` require `Win32EditCommand`; combining either with `-Play` is rejected in this tag. The plan omits them. Editor modes retain the editor after play; this is different from direct `-Play`. [AppCommands.cpp:143–156, 665–674, 783–810](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/core/AppCommands.cpp#L143), [main.cpp](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/core/main.cpp), [player.cpp:2235–2236](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/core/player.cpp#L2235).

2. **External close and saving.** SDL window-close requests set `CS_STOP_PLAY`. Player shutdown signals `OnGameEnd`, runs the table's exit event, stops script/plugin instances, saves table settings and writes a texture cache if enabled. ROM/plugin/script persistence has its own paths. Closing the editor while a player exists is rejected. The Hub's Windows card requests close on its owned child without a force timer; this is source/QML behavior, not proof of a particular table saving scores. Existing application teardown still has a force fallback, so VPX admission remains disabled. [player.cpp:863–916, 1494–1496](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/core/player.cpp#L863), [WinEditor.cpp:1391–1395](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/ui/win/WinEditor.cpp#L1391).

3. **Log and observable states.** `vpinball.log` is under FileLocator's Preferences path, which is distinct from a custom `-Ini` filename. Source markers include `PinTable Data loaded`, `Initializing player`, `Closing player...`, `Player closed.`, and `Closing VPX...`. They are diagnostic milestones, not a guarantee that a table is playable or a ROM is running. A plugin start/end event can strengthen process/window/log observations. [Logger.cpp:167, 213](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/utils/Logger.cpp#L167), [pintable.cpp:1545](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/parts/pintable.cpp#L1545), [player.cpp:355, 865, 1107](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/core/player.cpp#L355).

4. **VR and no headset.** `[PlayerVR] AskToTurnOn` uses 0 forced on, 1 autodetect, 2 off. Forced mode can show a retry dialog on missing HMD, or an OpenXR initialization error. Autodetect falls back when unavailable. Desktop preparation therefore uses 2; no Hub action changes the OpenXR runtime. Both `-Ini` and `-TableIni` are explicit owned paths, and the table INI must already exist. Neither redirects all writes. FileLocator's default layout writes cache/user folders beside the table; PinMAME's path includes both ROM reads and nvram writes. Arbitrary table scripts and plugins add further outputs. **No live launch until all of those outputs are isolated.** [player.cpp:252–278](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/core/player.cpp#L252), [AppCommands.cpp:816–828](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/core/AppCommands.cpp#L816), [FileLocator.cpp:282–339](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/core/FileLocator.cpp#L282), [PinMAMEPlugin.cpp:213](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/plugins/pinmame/PinMAMEPlugin.cpp#L213).

5. **Plugin feasibility.** The message API exposes game-start/end and prepare-frame subscriptions; the example cleans them up on unload. `GetInputState`/`SetInputState` can carry mapped actions. ExitGame is mapped; VRRecenter is an enum but its map is commented out. A small authenticated same-machine bridge is feasible for state and mapped exit input, but is not implemented or accepted here. Restart is a Hub operation after confirmed successful exit, retaining the exact route. Recentre is disabled with an explanation. The shipped network remote-control plugin is not activated. [helloworld.cpp](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/plugins/helloworld/helloworld.cpp), [VPXPlugin.h:267–276](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/plugins/plugins/VPXPlugin.h#L267), [VPXPluginAPIImpl.cpp:574–582](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/core/VPXPluginAPIImpl.cpp#L574).

6. **Attract capture.** The capture filename is the table's parent directory plus `Capture/` and generated QOI frames. This violates the read-only collection boundary; the Hub neither invokes nor offers it. Settings flags and working-directory changes do not redirect that expression. [player.cpp:1791–1804](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/core/player.cpp#L1791).

7. **Audit.** `-Audit` loads a table and calls `AuditTable(true)`. It reports script duplicate declarations/Execute usage, invalid glass geometry, rendering/physics/asset problems and related warnings. It is not a trusted VR-room classifier or ROM inventory. The Hub uses bounded metadata reads instead of invoking the engine audit, avoiding table load side effects. [AppCommands.cpp:158–167](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/core/AppCommands.cpp#L158), [pintable.cpp:4603 onward](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/parts/pintable.cpp#L4603).

The Quest controls are source-verified at [XRInputHandler.h:125–152](https://github.com/vpinball/vpinball/blob/af26b2d9392b4c9ec3e3edff4bbd69562085a44c/src/input/XRInputHandler.h#L125): triggers flippers, grips Magna Save, A start, B credit, X menu, Y exit, left stick nudge/click recentre, right stick plunger/click launch. These controller bindings do not imply an implemented Hub Recentre bridge.

`-PrefPath` option, preference setup before argument parsing, user score
