# R3 Viewer: bounded input-free capture preparation

The new ordinary-Dolphin capture supervisor prepares an isolated SBS profile,
checks explicitly supplied executable hashes and the scoped disc header, then
waits for its own game window and runs only the capture-only helper. It injects
no input, uses no Computer Use and initializes no SteamVR. It releases the
capture process before reaping Dolphin, with timeouts and private receipts on
failure. It never retries automatically or resumes an old output directory.

Nine synthetic harness tests pass, including an actual CPU-only child cleanup
after second-spawn failure. Fresh private preparation passed without launching
an application. Two full local runs each had one intermittent access-denied
staging rename in different existing profile tests; redirecting temporary
fixtures and running outside the sandbox did not eliminate it. The cause is
unproven and no production retry workaround was added. CI now discovers both
profile and harness tests.

Real WGC capture is pending a lead-coordinated runtime slot. Scripted DSU input
belongs to the lead. A system prompt stops the item for owner resolution; the
supervisor cannot detect unrelated prompts. Captured RGB differences never
establish actual game content or SBS by themselves: both PNGs require inspection.
Hardware texture submission, headset image/comfort, physical input, calibration
and timing remain open. Historical failed attempts and original WIP are preserved.

Entrypoint: `tools/wii-dolphin-profile/desktop_capture.py`. Operator contract:
`tools/wii-dolphin-profile/theatre/README.md`. Private configuration, content
paths, images and process receipts remain outside Git. No game content,
downloads, tool installation, runtime settings or ordinary Steam writes occur.
