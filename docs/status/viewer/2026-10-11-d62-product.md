# D62 Viewer: canonical product labels

Fresh ordinary-Dolphin profiles consume the shared product contract: `short_id`
provides safe filenames and `dsu_server_name` provides entries, devices and
cross-slot binding qualifiers. Their manifest retains the consumed labels, so
a later rename leaves existing profiles unchanged. All six exact historical
manifests remain admitted, including runtime-edited configs for launch commands.
Manifest filename/schema identifiers, receipts, calibration files and persisted overlay
ownership keys are preserved. Shared generated profiles are never rewritten;
an obsolete canonical DSU label fails admission before fresh preparation.

The theatre's visible title derives from `display_name` at build time. The
generated C++ contains escaped UTF-8 bytes, with a compiled quote/Unicode
regression. Invalid product metadata fails without creating a fresh user profile
or configuring a misleading fallback title. The shared JSON dependency is an
unchanged copy of the published contract, not a branding edit.

Thirty Python tests pass, including byte-exact historical manifest fixtures,
rename persistence, unsafe labels, tampering and calibration/receipt preservation.
MSVC Release /W4 /WX builds and nine native headless CTests pass; graphics tests
use software WARP. Privacy and whitespace checks apply to the final source.
No game, desktop, headset or hardware-graphics run occurred for D62. PR49's
accepted safety-screen SBS capture remains a separate historical checkpoint;
menu/mission, depth, physical input and headset gates remain open. Source and
headless results establish label handling, not renamed runtime presentation.

its prefix from canonical short_id, separately from its visible title.

only for the running viewer; cleanup uses the returned OpenVR handle, and
no manifest or external consumer stores or looks up its literal prefix.
