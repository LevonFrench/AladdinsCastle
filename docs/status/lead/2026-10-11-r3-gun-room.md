# R3 native gun-room source checkpoint

libacvr can create its own Windows desktop-GL OpenXR session when the optional
provider is enabled. The default build still has no XR dependency. The room
draws a floor, targets and aim ray; the provider draws authored guns, hands,
two-hand holds and inspectable part labels. Shared action labels remain
UNCONFIRMED until a resolved game route supplies verified mappings.

The hand consumer requires the PR54 assembly contract. Gun mounting follows
the explicit per-hand primary selector, independently of glove attachment;
both node and local transform participate in inverse placement and support
aim. Independent review caught the initial selector drift, and a regression
uses different glove/gun nodes with a rotated, translated mount. Unknown pose
and mounting nodes reject before XR creation.

Opt-in capture reads the actual acquired eye framebuffers after drawing and
before release, restores touched GL state, and writes fresh private PPMs and
a receipt only after frame submission. OpenXR view zero is left, independent
of the hand array order. A distinct-image regression guards that correction.
The room deadline is cooperative; an external supervisor must bound blocked
create, tick and destroy calls. A geometry SVG is not an eye capture.

Independent final native CPU CTest passed 12/12; the default-off build passed
5/5. Nine exact-commit asset probes passed. Source review closed mount, pose
validation and label-claim findings. Existing SDK headers and a locally built
cached-source loader suffice; no dependency was downloaded or installed.

No actual-eye run, tracked hand image, target interaction, physical fit or
headset acceptance is claimed at this source checkpoint. A null-driver attempt
requires backed-up settings, bounded ownership/cleanup and confirmed restore;
the owner sitting remains the acceptance gate for the complete room.
