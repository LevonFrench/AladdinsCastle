# Lead report 7 — compiled gun draw path and native-controls CI

## Done / verified

Added an original MIT programmable GL gun renderer, with the existing native
model loader's transformed and tinted geometry as its upload path. It uses a
desktop GL 3.3 compatibility context, draws opaque and sorted translucent
geometry into the runtime's borrowed colour/depth attachments, and restores
caller state. It never clears or detaches the shared world depth. Attachment
identity, resource creation, malformed packets, failures and owner-thread use
are covered by CPU mock dispatch tests. See `docs/libacvr-gun-gl.md`.

Strict MSVC and installed GCC builds pass all six CPU suites, including
cross-thread and core/GLES rejection assertions. These tests make no driver calls and do not establish pixel output.
An optional Windows synthetic GPU executable also compiles with the installed
Qt SDK. It is excluded from CTest and hosted CI, checks its explicit approval
flag before platform initialization, and has not been run.

CI now compiles the gun renderer and runs its CPU tests. A conditional native
controls job will configure the lane's standalone component with the existing
toml++ dependency, then run its native resolver and software Qt tests once the
lane lands. This CI wiring does not claim acceptance of the unmerged component.
Checkpoint `99aba45` passed the hosted PR Windows/Linux/catalog checks.
