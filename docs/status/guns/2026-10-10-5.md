# Guns block 5: handedness review corrections

Draft PR 10 remains the integration surface. This block addresses the lead's
independent review of block 4 before the requested source-model audit.

## Fixed behavior

Both resolvers now expand slot-local primary and fallback bindings using the
final `policy.p1_hand`: slot 0 uses that hand, slot 1 the opposite. Absent policy
defaults to right. Before the fix, a left-handed primary trigger plus an explicit
right trigger action was incorrectly rejected, while an explicit left trigger
collision was missed. The same inversion affected the pump's flick fallback.
The new Python regression reproduced all four failures before the correction.

The view resets its hand to right on every clear/load, then applies the current
resolved hand if present. Loading a left-handed game followed by an absent or
deleted policy cannot inherit left from the previous game or transient preview.
Host runtime hand changes must go through resolution before loading the result;
`setPrimaryHand` is a transient preview override, cleared by replacement. No
persistence or new profile layer was added.
