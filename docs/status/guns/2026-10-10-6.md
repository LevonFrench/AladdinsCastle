The builder creates a sole identity `grip` root. Muzzle, effects, sights and the
mounted second grip are direct children, outside driven LOD hierarchies. Muzzle
translations are forward along -Z with identity orientation. Every motion has
one canonical LOD0 target and a `_lod1` target, with matching semantic extras;
targets are unique across drivers. Metadata IDs, supported drives, unit axes,
increasing finite ranges and durations match the native contract. The existing
Python source tests cover these plans, button sets and mounted hierarchy.

The four used material roles have finite RGBA values in 0..1, alpha 1 and no
textures. The toy lens intentionally uses an opaque `glass` role. Native GL
chooses blending from final vertex × base × tint alpha; transparent owner tints
are a separate runtime behavior and need no transparent source lens.

## Proposed corrections, not implemented

1. **Slide-only geometry:** `arc-pistol-slide` currently gives the guard rails,
   cable boss and grip ribs the `slide_recoil` parent. Keep those stationary,
   with the trigger/frame/grip, and retain recoil on upper slide geometry and
   its visible sight/lens children. Static sight markers remain independent.
   Add a source regression checking the stationary versus moving part sets.
2. **Tint parity:** the GL packet builder multiplies body/accent base RGB by the
   supplied tint. The source exports grey body .55 and accent .32/.32/.34, while
   previews replace those RGB values with the full p1 tint. Prefer white neutral
   body/accent export for direct palette parity, or multiply previews by the
   neutral base values too. Preserve fixed dark/glass RGBA and export-before-tint.
3. **Mounted rest state, lead runtime lane:** yaw [-.7,.7] and pitch [-.4,.4]
   need normalized value .5 at rest. `GunInstance::reset/clear_motion` initialize
   value 0, and `draw` maps it to the minimum; current runtime has no yaw/pitch
   center initialization. Use the agreed centered neutral convention for reset
   and cancellation; do not change the signed source ranges to hide this issue.
4. **Checker parity:** the actual-asset checker currently checks motion node,
   range, alias extras and axes, but not supported drive names, duration bounds,
   duplicate drivers or animated ancestors of every static sight/second-grip
   reference. Add these guards plus finite material RGBA checks when source work
   resumes. They are supplemental checks; the native decoder remains its own
   acceptance gate.
