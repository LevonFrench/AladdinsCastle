# R4 weapon prototypes: source checkpoint, visual work incomplete

Five original scripted weapon props replace the earlier per-game stand-ins: one service pistol shared by both Resident Evil games, a heavy revolver for Overkill, an industrial tool gun for Dead Space, a crossbow for Link and a fictional energy gun for Sin & Punishment. No imported, traced or extracted geometry, maker marks or new downloads. Existing nine gun meshes and their hand mounts remain unchanged; the mounted gun retains its older finish.

| Prototype | LOD0 / LOD1 triangles |
| --- | --- |
| Service pistol | 4084 / 712 |
| Heavy revolver | 5840 / 772 |
| Industrial tool gun | 4644 / 712 |
| Crossbow | 4072 / 864 |
| Energy gun | 3932 / 700 |

All fourteen actual assets pass the existing checker: units, axes, required nodes, four used materials, bounds/contact, budgets and clear bore-parallel notch/blade sights on both LODs. Trigger, reload control and slide/cylinder/string motion nodes have limits and aliases; game-event wiring remains unverified. Both hand mounts and moving label anchors are compiled from the authored data. Twenty-four hand cases produced forty-eight CPU images, including supported crossbow/mounted holds and faithful shell docked poses.

One [weapon/hand/reload/label sheet](../../../assets/guns/preview/wii-proposal-sheet.png) includes both sight-detail checks. The refreshed [Umbrella controls example](../../../assets/controls/wii/umbrella-shell-stick-controls.png) still shows shell and stick from the shared route data. All generated button-profile bytes are unchanged by the weapon choices. Reloads stay disabled/questions; option/instruction screens, gun choices and physical fit are unaccepted.

Validation: all twelve registered CPU checks pass (eleven data/native suites plus the full software view suite, fourteen Qt cases); existing source/control regressions and privacy checks pass. Blender 5.2.1 ran sequentially with four CPU threads, Cycles64 and CPU denoising. Final model/hand batch exited0, Blender quit and visible Blender processes were zero. Earlier failed batches remain in private logs; no GPU or game/headset runtime was used.

Lead viewed the sheet and did **not** accept realistic finish: current diffuse grey/blocky views still read as prototypes, particularly the revolver cylinder. Exported metal/rubber PBR parameters do not prove the current runtime's appearance; its diffuse recipe has no metallic/specular response. Publish this as WIP source/evidence, with visual finish, game-event motion, native aim and headset fit still open. Measured desktop DSU aim was published separately in PR79 and is integrated into next; it is not native/headset acceptance. No new validation framework or GPU request is part of this checkpoint.
