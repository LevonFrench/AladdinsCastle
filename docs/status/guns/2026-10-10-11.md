## Repro 1: alternate coin hold plus default coin press

Retain the baseline p1 coin on slot-local secondary press. Add a virtual element
with a distinct ID, slot/player 0, `input = {kind="button",semantic="coin"}`,
and `binding = {hand="slot",control="primary",mode="hold"}`. These use different
physical buttons and are valid in the resolver.

Both hands stay tracked. Samples at 0, 17 and 34 ms:

1. Both buttons released.
2. Hold right primary.
3. Keep primary held and press right secondary.

At immutable `dd5ea6c`, creation and the first two runtime ticks return OK; the
third returns `BAD_ARGUMENT` (-2). `controls.cpp:151-152` ORs the same semantic's
HELD and PRESSED into mapped state 3. `runtime.cpp:551-555` accepts only 0, 1 or
2 from mapped buttons, rejecting that valid aggregate. Its subsequent pulse
logic at line 583 would also force release of the concurrent hold if the gate
alone were widened. This concerns mapper output, not ordinary outgoing native
HELD|PRESSED snapshots, which are valid ABI input.

## Repro 2: either-grip inverted cover

Add a virtual cover element with slot/player 0,
`input = {kind="axis",semantic="cover_pedal"}` and
`binding = {hand="either",control="grip",mode="hold",invert=true}`.
The non-inverted baseline semantics in `docs/controls.md` are either held grip
exposes; its inverted hold-to-cover option covers while either grip is held.

Both hands stay tracked. Begin with both grips released, then hold only right
grip while left remains released. The same fixture with `hand="slot"` sends
pedal values 1, 0, 0. With `hand="either"`, immutable `dd5ea6c` sends 1, 1, 1:
the player stays exposed. `controls.cpp:134` inverts each hand before OR; the
released other hand therefore forces a true result. Invert the aggregated
physical action after OR, retaining the neutral result when no hand is tracked.
