## P2: admitted positive UV endpoint fails texture preparation

`setups/namco22-vr/src/material.cpp:18-20` admits UV coordinates with absolute
value up to and including 65536. Its direct sampler at lines 43-45 admits the
same endpoint. However, `setups/namco22-vr/src/texture_plan.cpp:43` samples each
rectangle cell at its centre. A cell whose minimum is 65536 is sampled at
65536.5, which the direct sampler rejects. Thus a valid packet can fail before
rendering even when the required wrapped sparse cell and palette entry exist.

An original CPU probe used one triangle, a Fixed16 material, palette entry 1
equal to 0x123456, a tile filled with pen 1, and explicit wrapped boundary cells.
All three vertices used the indicated UV and brightness 64:

| UV | Vertex valid | Direct sample | Texture plan |
|---|---|---|---|
| .5, .5 | yes | OK, 0x123456 | OK |
| 65535.5, .5 | yes | OK, 0x123456 | OK |
| 65536, .5 | yes | OK, 0x123456 | BAD_ARGUMENT (-2) |
| .5, 65536 | yes | OK, 0x123456 | BAD_ARGUMENT (-2) |
| -65536, .5 | yes | OK, 0x123456 | OK |

The failed calls retain the previous output plan. This is a mismatch between
admitted input and internal sampling, rather than a missing cell, oversized
rectangle, GL error or target-clear failure. Align internal integer-cell
sampling with the public UV domain, and cover both positive endpoints with a
regression case. No patch was made in this review lane.

## Saved-state and lifecycle findings

No additional actionable defect was reproduced within this bounded review.
Source inspection covered the following paths, with existing CPU mocks executed
independently using the existing strict MSVC toolchain:

- Extents and complete lease budgets are checked before pixel allocation;
  exact material/minimum/extent keys deduplicate uploads. Raw texel-centre UVs
  are normalized without an additional half-texel or native inverse-depth divide.
- The saved-state guard restores on normal exits and exception unwinding.
  Unit-zero binding, sampler, texture matrix and pixel-unpack state have explicit
  restoration alongside legacy attribute stacks and modern enables/selectors.
  Altered optional imaging state rejects before upload or target clear.
- Uploads use owned CPU pixels and explicit sampling/transfer state. Allocation
  and upload failures roll back owned texture names; borrowed attachment names
  are excluded. First-eye uploads persist across second-eye and pose replay.
- Owner-thread release/shutdown retire cached textures before dropping the CPU
  lease. Draw failure retains the known lease for cleanup. Wrong-thread calls
  reject without dispatch; duplicate release/shutdown are idempotent in mocks.
