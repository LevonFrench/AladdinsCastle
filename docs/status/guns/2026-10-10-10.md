## Remaining actionable gaps

### P2: resolved switch policy can disagree with runtime config

`controls.cpp:40-43` reads only `policy.p1_hand`. `runtime.cpp:379` initializes
`hand_switch` solely from the C config; the create consistency block at
`runtime.cpp:438-444` checks model ID and primary hand, not switch policy.
Consequently, resolved TOML `policy.hand_switch = "off"` plus C config flag 1
is accepted and the other-trigger gesture still switches hands. This is distinct
from the primary-hand/model consistency checks, which are present.

If resolved TOML is authoritative for this known policy, derive it or reject the
conflict before create succeeds. If effective policy intentionally belongs only
to the Host/C config, document that boundary and require the host to verify its
consistency with the resolved controls view. Suggested fixture: matching model
and primary hand, conflicting switch settings, then a tracked other-trigger edge.

### P2: resolver-valid off-screen customization aborts runtime creation

`controls.cpp:78` restricts the composite to non-inverted slot reload press;
`controls.cpp:81-82` additionally requires matching non-inverted, non-toggle
slot trigger fire with exactly equal threshold. Published v0.1 permits explicit
hands and optional thresholds/invert; the current lane resolver does not impose
that extra pairing rule.

Executed source resolver check: `timecris` with only the p1 fire threshold
overridden to .8 resolves successfully; off-screen reload keeps default .55.
The mapper's equality requirement then rejects that valid resolved file, and
`runtime.cpp:434-435` converts preparation failure to create `BAD_ARGUMENT`.
No mapper execution was used for this conclusion.

Make composite normalization/validation consistent before handoff, or report
the unsupported customization as unavailable while retaining valid fire. Avoid
changing the composite into a second fire event. Add trigger-only threshold and
single-gun explicit-hand cases to the resolver-to-runtime boundary tests.

### P2: loaded-model input node references are unchecked

`controls.cpp:47` reads and discards `element.node`. The mapper receives no
decoded-model node set, and runtime create never checks these references against
the already loaded asset. A resolved input can name a nonexistent model node
while its gameplay action still becomes active. This cannot establish the
part-to-action/model-reference acceptance promised by v0.1 validation.

Validate each nonempty active reference against the actual decoded model, or
require an explicit already-validated node contract from the host. Empty virtual
pedal/menu nodes remain valid. Suggested fixture: correct model/hand, declared
coin/fire, but nonexistent named node; keep unknown extension fields unchanged.
Separately, node-to-button-motion wiring remains unimplemented: the current
runtime only drives trigger/recoil, so actual model button press animation must
remain a stated gate rather than inferred from mapped game input.

## Confirmed source behavior and scope

- Slot-local bindings use the current primary hand, with explicit left/right
  and either-hand expansion. This path supports one active gun; slot 1 stays
  unavailable, and runtime create rejects multi-gun backend capacity. That is a
  declared proof scope, not two-gun acceptance.
- Trigger/grip threshold, invert and latch state are parsed; cancel/tracking loss
  rearm requires release. Latest fire/button press modes queue native pulses;
  press-mode axes are explicitly unavailable. Reload press currently becomes a
  held level consumed once on its native rising edge, which preserves one reload
  request per physical press.
- Off-screen reload is an enable predicate over the native fire edge plus aim:
  `runtime.cpp:203-208` blocks that edge from also firing. No duplicate independent
  fire port was found.
- Axis/button declarations and runtime-action capability masks gate emission;
  unavailable element IDs are reported to Host. Unsupported pump/slide/flick
  interactions stay unavailable, and their raw source survives. No gesture,
  Start port or output channel is inferred.
- Output references are motion IDs, correctly validated by
  `gun_model.cpp:152-163`; duplicate target motions and unknown IDs reject before
  activation. Consume uses rising edge/once-per-native-tick, cancellation and
  configured-route recoil exclusion. Unsupported other-slot/player output rows
  are filtered; they are not reported as unavailable outputs by this mapper.
- `candidate.original`/`source()` retain the exact resolved text, including
  unknown extensions. There is no second merge implementation or persistence.
