## Done

holder could crash after OS spawn but before the started callback recorded its
child. A synthetic protocol reproduction failed its exclusion assertion while
the owned child was still alive; this supersedes the old head's green CI.

Every payload now receives durable pending evidence before attempting spawn.
A partial marker write prevents spawn. The started callback replaces pending
markers with PID/creation evidence. A live holder clears pending reservations
only when it knows spawn was not attempted or its process is stopped. Pending
evidence survives abrupt holder exit and requires operator review; no timeout,
automatic deletion or destructive recovery is used to guess that a child is gone.
Diagnostics explain this refusal. Scope/limits remain in `hub/SHARED_LOCKS.md`.
