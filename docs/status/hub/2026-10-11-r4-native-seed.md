# R4 native profile seeding

The existing pinned-byte installer seed policy admitted generated controller profiles but rejected the authored native game profile. A failing-first, CPU-only `hubtool plan` with synthetic shader bytes reproduced `E_SOURCE_OUT_OF_SCOPE`; no installation or executable launch occurred.

The source change admits exactly `data/profiles/dolphinxr/GameSettingsVR/RBUP08.ini`. Existing SHA256, byte-cap, path/link/media-alias, explicit-create, absent-only and no-key-merge checks still apply. Synthetic engine tests cover exact CRLF/comment/bare shader-name preservation, a preexisting user profile, repair/update/uninstall preservation and four unrelated-path refusals.

Hosted Linux testing found a traversal fixture error before the policy check: creating the literal invalid fixture path failed. The correction normalizes only its private file location, retains the malicious recipe source and real pin, and still requires `E_SOURCE_OUT_OF_SCOPE` with no output. A bounded offline MSVC build of only the installer target and CLI succeeded; all 25 focused installer cases passed, including exact authored bytes and the corrected traversal row. Build/test processes closed and the CPU slot was released. Final hosted checks for this fixture-only correction remain pending.

The Umbrella recipe now seeds the native game profile with the exact SHA256 verified after PR75 integrated into published `next`. Recipe coverage checks its absent-only declaration and pin; an actual-profile engine regression copies the authored bytes into a temporary synthetic fixture and requires exact output, including its bare enabled-name lines. The lead owns the sitting-kit copy separately. The profile remains a fixed-scene candidate; 4x/headset acceptance is pending. This branch has no software installation, download, game-file access or GPU/runtime result.

The Viewer design is the basis for the next capture proposal. An explicit one-shot request runs after render/submit and before `QuickTextureRenderer::doneCurrent`, reading the same renderer texture through a temporary read framebuffer. Preserve read-FBO/read-buffer, pack-buffer and pack-layout state on every exit; leave draw state untouched. Convert bottom-first GL rows once and retain that source-texture PNG, with mirror, picture UV bounds and pointer Flip Y recorded separately. Crucially, `submit()` currently returns true for a hidden-overlay no-op: an API-submitted claim requires a diagnostic result set only around the actual `SetOverlayTexture` call, including its return code. API success and raw texture pixels still do not prove compositor display or pointer/headset acceptance. Opt-in asymmetric QML corner markers, confined fresh outputs, one-attempt lifecycle and GPU-free row-conversion/GL-state/hidden-submit tests are part of the proposed implementation. No capture implementation or GPU execution has occurred.
