## Recommended next gap

Copy and apply the Super22 mixer's background RGB in each world's existing scoped
clear. Current CPU and GL paths always clear black. This is the smallest actual
composition step that does not depend on native sprite/text priority or choosing
new shade/fog/fade saturation semantics. Native Time Crisis admission stays zero.

Authority: generic `namco22-decompile` pin
`a9f1a0a1f9de62387a7138006fa36933fd477123`. `engine/fog_hw.c` copies mixer bytes
0x08..0x0a into background RGB. `engine/ss22_gl.c:492-493` clears that RGB before
polygon/sprite drawing and the later screen fade/text/gamma stages. Existing
source/hash guards cover these generic files; no game-source lookup is needed.

Add a small private, explicitly absent/Super22-background policy with owned RGB
and same-tick identity, separate from CZ fog and material state. Decode only the
existing copied `VideoSnapshot` mixer bank after its length/tick checks, then copy
the value into the usual immutable Frame. Absent policy keeps synthetic black.
Apply it to uncovered world pixels; opaque geometry/backdrops replace it as now.
Both eye/replay draws use the same frozen value, with depth clear 1, opaque alpha,
the same scissor and exactly one existing clear. Keep the standalone HUD-only CPU
image policy unchanged. No new GL resource, blend pass, shared ABI or factory.

Synthetic CPU/GL mocks: empty coloured world, polygon-covered versus uncovered
pixels, nonzero eye rectangles with untouched neighbours, paired/replayed eyes,
producer mutation after publication, absent/invalid-policy/tick/length rejection
before clear, hostile ClearColor restoration and identical depth/raycast. Reuse
strict MSVC pinned-source/GCC suites and privacy checks; no GPU/native execution.

## Dependencies and later composition

This follows PR23 acceptance on a new dependent branch and leaves that reviewed
head untouched. Background is input to later screen fade/gamma, not a substitute
for either. Do not fold fade/gamma into background, fog RGB or palette here.

Polygon fade still needs an explicit source-policy decision: generic `ss22_gl.c:61-67`
multiplies enabled channels by byte/256, but `quad_gl.c:794-827` folds it into inputs
before combiner saturation. It cannot silently become an after-clamp multiply.
Screen fade (`ss22_gl.c:517-533`) covers background/world/sprites before text;
text/sprites have separate gates (`text_hw.c`, `sprite_hw.c`). Gamma (`post_gl.c:1-14`)
acts on the final composed image. Native ordering/layer admission must precede
claims of complete composition. Those stages are not part of this proposal.

No implementation, board expansion, install/download, game/BIOS/generated-source
access or actual GL/GPU/headset/Steam use is authorized by this proposal alone.
