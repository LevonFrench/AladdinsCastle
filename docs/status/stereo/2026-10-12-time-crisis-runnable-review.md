# Stereo: current Time Crisis runnable review

**Done:** Source-only review of the current private launcher, its build-manifest binding and the native stereo producer. This focuses on the actual launch and scene path, extending the earlier prototype review. No game assets, captures or original reference files were read or changed. No build, game test, GPU run, download, validator or packaging work was performed.

**Both-eye path:** The native loop prepares one board update before periodic capture and desktop presentation. Each eye rewalks the same latched polygon callback with a horizontal view-space offset before native culling, clipping and projection; layer state is prepared once and no emulation tick occurs between eyes. Left/right offsets are -32/+32 original game units. Native viewport, focal length and fixed-point projection remain in use. The two 640x480 targets blit into a 1280x480 desktop window, with only the first blit clearing the destination. Capture frames perform two capture eye draws plus two display eye draws from that same update. This synchronous callback is live board RAM, not an immutable frame lease.

**Launch scene:** Stage1 is supported by the native cabinet-input script. From power-on it begins three coin pulses at frame300, aims and fires at Timed Game, then stage1, and releases control at frame1200. The explicit2400-frame limit survives the window-launch path and leaves up to1200 simulation frames after handoff. This can drive the normal timed-game start under normal boot/menu timing; it does not prove that a particular playable scene appears before the limit. The native mode log can distinguish game from attract output during a future booked run.

**Screen-space and input limits:** Sprites, text and screen effects retain their native screen placement in both eyes; there is no new physical HUD depth or headset tracking. Stereo presentation bypasses ordinary host overlays and gun-picture bookkeeping. Mouse/absolute-gun aim after handoff is therefore unsupported. That does not invalidate the stage script, which owns the gun inputs until it finishes. The current unattended launcher supplies no pedal after handoff, so a real scene can remain in cover. An existing finite digital pedal script is available if later images establish that need; no change was applied.

**Run-blocking conditions and acceptance:** No unconditional source blocker was found for the default arguments with working content, inputs and GL. Missing content/program/DSP and window-video initialization can stop the run; missing sound MCU prevents game inputs. Offscreen framebuffer support is required for both eyes, but an unavailable eye target currently returns without forcing a failed game exit. Exit0 alone therefore proves neither eye output nor a real scene. The wall deadline can also stop a slow run before2400 frames. All actual runtime conditions remain unverified by this review.
