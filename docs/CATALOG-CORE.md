# Catalog core integration (M1 lane C)

The catalog loader produces plain value types. `GameListModel` owns the result on the GUI thread; the desktop startup runs loading on a QtConcurrent worker before exposing the model. Unknown TOML keys remain in the JSON records. Leaf provenance uses JSON pointers and metadata paths relative to the selected catalog root.

## Public interfaces

- `core/catalog/CatalogLoader.h`: `CatalogLoader::load(root)` returns `CatalogData` containing games, vocabularies, emulator manifests, shared setups, theme tokens and the validation report. `parseToml(file)` and `merge(base, layer)` are reusable by the install lane.
- `core/catalog/GameRecord.h`: `GameRecord` retains `raw`, `install`, per-game `setup`, corresponding provenance maps, variants, derived roles and runtime state. `validationErrors` contributes to validator error counts, while these diagnostics remain nonblocking `loadWarning` values. Parse failures and duplicate declared IDs set `loadError`.
- `models/GameListModel.h`: `find(id)`, `records()`, `catalog()`, `roleForName(name)`, `applyRuntimeStates(states)` and `queueRuntimeStates(states)`. Runtime value types are Qt metatypes. Workers must deliver values to a GUI-thread callback; they must never call model mutation methods directly. Queued batches coalesce by game ID at intervals of at least 80 ms. Updates emit only changed roles and never reset source rows.
- `models/FilterSortModel.h`: `setFacet(name, value)`, `facet(name)`, `choices(name)`, `clearFacets()`, and properties `query`, `sortMode`, `visibleCount`, `scanComplete`. `GameFilterModel` aliases this class. Unknown facet values are discarded and produce `filterWarning`; an entirely invalid selection clears that facet. Wrong scalar types and reversed year ranges are ignored.

Facet names are those in UI model spec section 7.1: `genre`, `statePills`, `inLibraryOnly`, `hardwareIds`, `manufacturerIds`, `yearMin`, `yearMax`, `graphicsIds`, `vrKeys`, `playersBuckets`, `controlsTypes`. Additional helpers are `hardwareKinds`, `hardwareFamilies`, `decades`, `hiddenPublishers`. List facets accept QStringList or QVariantList. Hardware selections also accept kind, family, or `kind/family` nodes. `scanComplete` enables state and library predicates; it defaults to false. Sort keys are `title`, `year`, `manufacturer`, `hardware`, `recent`, and the proposed `added` mode.

`RuntimeState` is a complete snapshot for one game. Populate `mediaFound` with requirement identifiers from `Variant.media`, `toolsOk`/`toolsOlder` with emulator IDs, and variant installation gates with `VariantRuntimeState`. An install requires `verified`, `installedWhenExists` and `manifestExists` together; existence alone never makes it Installed. `selectedVariantId` selects a playable detail-page variant. Job overlays retain `baseState`. Art provenance and play timestamps are carried through the same value type.

## Spec resolutions and boundaries

- The repository currently has no `schemas/` directory and no controls vocabulary file. The loader implements the Python catalog validator's checks directly, plus the UI-required players, controls, duplicate-ID and safe-type diagnostics. Unrecognized fields are preserved. The real metadata catalog contains 413 records and zero validator errors; its two warnings identify empty metadata source lists, matching the Python validator. Missing controls types render as `other` / Unknown.
- Newer game-packages section 4.1 takes precedence over the older UI NoRecipe rule: generated flat emulator routes can resolve needs/ready state without an install.toml. `hasRecipe` continues to mean an authored install.toml. Basic generated variants carry launch metadata and needs; executable substitution, portable install recipes and actual launching belong to lanes E/G. An authored variant with the same emulator ID wins.
- Generated media requirements use catalog set, serial or explicit ID keys. Matching and verification policies belong to lane F; this lane never scans owner folders or accesses game content. A populated `mediaFound` requirement counts as found for state resolution, resolving the open found-but-not-verified state question conservatively at the interface boundary; lane F decides what evidence qualifies for its result.
- Planned true 3D remains a separate mark when Theatre is available. Badge player counts come from `players`; the raw 2/3-player tags do not override it. Both raw WIP tags and variant WIP statuses count. Manufacturer short labels fall back to the vocabulary label. Horse racing has no Explore bucket pending the owner decision. Proposed firstSeen/new and added sort use runtime timestamps.
- The minimal desktop list supplies filters and a warnings popup. It performs no scanning, installation, downloads, launch, Steam writes or authentication. Lane D owns the production interface and local art provider.

## Verification

CI CTest includes `hub-catalog`, with synthetic metadata fixtures for layered tables, array merges by ID, deletion and provenance, unknown fields, every filter facet, malformed selections, AND/OR combinations, search grammar, stable tie ordering, scan gating, install proof gates, duplicate/type diagnostics and partial runtime updates. The real-catalog test loads all 413 metadata entries and checks zero errors. `hub-smoke` retains the displayless Unicode catalog-root launch check.

`hubtool [--data-root <root>] explain <game-id>` returns JSON for the merged game, authored install, per-game setup, generated/authored variants, provenance and diagnostics. The command reads metadata only. Local receipts are retained under `.local/` and must not be committed. Owner-operated visual acceptance remains separate from displayless startup and model tests.
