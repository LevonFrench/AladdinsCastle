# Ordinary Dolphin fallback profiles

Stdlib Python creates a **fresh isolated user directory**, not a copy of an
existing Dolphin User or NAND. Run from this checkout. No downloads, process
launches, game reads, Steam edits or system changes occur in the setup tool.

```powershell
python tools/wii-dolphin-profile/setup.py create --user .local/wii-profiles/one-gun/User --mode one-gun
python tools/wii-dolphin-profile/setup.py create --user .local/wii-profiles/two-remotes/User --mode two-remotes
python tools/wii-dolphin-profile/setup.py inspect --user .local/wii-profiles/one-gun/User
python -B -m unittest discover -s tools/wii-dolphin-profile -p test_profile.py -v
```

`--user` must be beneath this checkout's `.local`, without symlink/junction
ancestors. Existing directories without our manifest are refused. Rerunning is
safe only while all generated files match; Dolphin edits are preserved and
reported. Use another fresh directory to change mode. `inspect` verifies exact
generated bytes, not whether Dolphin has successfully loaded them. `command`
instead validates a recognized managed manifest and safe regular file paths,
accepting configuration legitimately rewritten during runtime without changing
any files. It rejects an unowned user directory, tampered manifest or linked
manifest/configuration/ancestor. Both initial and current generated manifest
templates are recognized; current defaults apply only to new directories. D62
reads `data/product.json`: fresh profile filenames use `short_id`, and DSU
entries, devices and cross-slot bindings use `dsu_server_name`. New manifests
retain the consumed labels so changing the product later does not migrate an
existing profile. All six exact pre-D62 manifests remain admitted, including
runtime edits for `command`. Historical manifest filename/schema identifiers,
receipts and calibration files are retained. Tests use
synthetic temporary directories; set TEMP/TMP to an owned local test directory
when the host sandbox's default temporary location is inaccessible.

The tool writes DSUClient.ini, WiimoteNew.ini, named profiles, GFX.ini and
per-game selectors for the PAL releases RBUP08 and SBDP08.
These remain the legacy default pair. The capture preparer's explicit generic
recipe instead creates only its selected six-character ID, retaining the same
schema and rejecting reuse of an existing User for a different game. No new
owned-title list or file discovery is embedded in the tool. Cheats are
disabled; no 60fps research codes are included. Analytics and the automatic
update track are disabled in fresh profiles, with the analytics permission
question marked answered. This does not modify a currently running profile.
DSU connects only to the canonical product server label at 127.0.0.1:26760.
Device0 is right hand; device1 is left hand. Unsafe filename or DSU protocol
delimiters fail before fresh profile creation. A canonical generated DSU profile
with an obsolete label must be regenerated by its producer, rather than silently
rewritten by this consumer.

| Control | Dolphin input |
|---|---|
| Trigger | Remote B / fire |
| Primary A/X | Remote A / interact |
| DSU Options | Remote +; usable Touch mapping pending |
| Absolute aim ray | IR via right-stick axes |
| Thumbstick | Nunchuk stick |
| Grip | Nunchuk Z |
| Secondary B/Y | Nunchuk C |
| Physical acceleration and rotation | Remote Motion Input |

One gun uses a right-hand Remote and cross-device left-hand Nunchuk. Two
Remotes use independent hand feeds, with each Nunchuk sharing that hand's feed.
Two physical controllers cannot produce four independent motion poses. Nunchuk
has acceleration, not a gyro. DSU Y positive is up; physical sign verification
remains a live gate. Dolphin converts DSU g and deg/s internally. No extra unit
scale is applied. Gyro-driven IR is disabled so it cannot compete with absolute
aim. Shake/Swing inputs remain blank; bridge R/V motion waveforms use the same
physical Motion Input path and must not be bound a second time.

Touch's right application-menu action is unavailable to the bridge. The
profile's DSU Options-to-Remote+ mapping is authored, but a usable physical
menu/Start binding is pending; do not claim the application-menu button works.

To print (never execute) an isolated launch command, supply explicit executable
and selected game paths using `command --user ... --dolphin ... --game-file ...`.
Omit `--game-file` to print a controller-configuration launch. Keep that output
private. The actual command is `Dolphin.exe --user <isolatedUser> -b -e
<gameFile>`. Launch coordination belongs to the lead.

GFX uses side-by-side stereo, depth20, convergence20 and unswapped eyes. This is
**3D theatre**, a fallback to the project's true-3D scene target. SteamVR
Desktop alone is not an SBS decoder. The theatre helper below is an original
bounded Windows.Graphics.Capture viewer; its actual game-render capture must be checked.

Source contract checked against DolphinXR v0.4 commit
85c4266b29eb308d173fefa0f21f5cb77df3516a, specifically
DualShockUDPClient.cpp, InputConfig.cpp, ControlGroup.cpp, Nunchuk.cpp and
GraphicsSettings.cpp. These keys are checked against that source. The newer StereoPerEyeResolutionFull key is omitted.
Binary key presence and source matching are not runtime acceptance.

## SBS theatre helper

See theatre/README.md. Builds use only the existing OpenVR SDK and
toolchain. No game or VR launch is part of the CPU test commands.

Fresh profiles set Display/RenderWindowWidth = 1280, RenderWindowHeight = 720
and RenderWindowAutoSize = False. Pointer full ranges are IR/Total Yaw =
77.319617 and IR/Total Pitch = 48.455491 degrees, derived as twice atan of the
plane half-extent over its 2 m distance. Pinned Cursor.cpp declares these names
and converts the full degree ranges to radians. IR/Hide = Square is scoped to
each Remote default device; the bridge selects edge or hide off-screen policy.
This assumes the calibrated plane centre and origin; verify its four corners
with the real controller. Existing user directories are never migrated.
