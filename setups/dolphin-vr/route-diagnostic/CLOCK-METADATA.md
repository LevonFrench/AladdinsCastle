# Optional clock metadata — source proposal

The existing CSV schema, sample interval, row/byte/time limits and route admission stay unchanged. This source has no native compile or runtime evidence yet. Apply the reviewed route patch to a fresh owned private source tree using `apply.py`; keep older source, candidates and observations intact. Independent source review precedes publication, compilation and any future run.

Alongside the existing CSV opt-in, `AC_DOLPHIN_VR_ROUTE_METADATA` optionally names a fresh absolute metadata file. Opening uses exclusive creation and never overwrites an existing record. A metadata open failure leaves CSV sampling alone. The sidecar emits **one finalized logger-origin-and-stop JSON record**, at most 4096 bytes, when the CSV closes. It contains no path, game identity, geometry, pixels, resource names or addresses. A forced process exit can leave it empty or incomplete; missing metadata proves no stop cause. No record is synthesized for a CSV that never opened successfully.

On Windows, the origin captures QPC-before, UTC FILETIME and a `steady_clock` anchor, then QPC-after. UTC and the steady anchor lie inside that QPC bracket. `logger_elapsed_at_anchor_ns` locates the anchor relative to the existing CSV elapsed origin. QPC values are signed ticks with an explicit frequency; UTC uses unsigned 100 ns units since 1601; CSV elapsed stays milliseconds. Preserve 64-bit JSON integers without floating-point coercion. Unavailable clock readings are explicit and cannot support a clock join. QPC comparisons require independently established provenance from the same host boot; the record does not contain a machine identifier.

Final counters count completed frame events, complete rows and complete CSV bytes. Stop reasons distinguish row, byte and elapsed limits, frame-counter overflow, write/flush errors and logger destruction. The first terminal cause survives destruction; `csv_close_ok` separately reports close/flush failure. `logger-destroyed` is not a natural application exit assertion. Partial writes can leave physical CSV bytes beyond the complete-byte counter. Metadata failure cannot promote a failed CSV or prove coverage.

Accepted capture receipts add `clock_metadata` without changing their existing schema or RGB/spatial/selection gates. Each of the two accepted frames retains full WGC `SystemRelativeTime` in 100 ns units plus a QPC/UTC acquisition bracket before pixel readback. The existing millisecond gate is unchanged. WGC's timestamp denotes compositor rendering, according to [Microsoft's API reference](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.direct3d11captureframe.systemrelativetime); it is neither a Dolphin submission timestamp nor an OpenXR presentation guarantee. QPC/UTC semantics follow [Microsoft's timing guidance](https://learn.microsoft.com/en-us/windows/win32/sysinfo/acquiring-high-resolution-time-stamps). Acquisition and rendering times are separate. UTC adjustments remain possible; compare QPC only with verified common provenance. A clock interval overlap cannot assign a logged draw to an exact captured GPU frame.

Old CSV/capture evidence lacks this explicit origin and the two full frame timestamps. File creation times and supervisor polling permit approximate correlation only; the new source cannot retroactively synchronize those artifacts. Original projection samples do not establish active XR routes, FOV, mission, stereo or performance acceptance.

`clock_metadata.py` validates bounded records and uses rational arithmetic for a host clock interval. Run its synthetic protocol tests with Python. Native `test_route_trace.cpp` adds real logger sidecar/exclusive-create/stop-cause checks for a separately authorized CPU compile; those checks are authored but unexecuted in this source-only task. No production launch configuration enables this opt-in automatically.
